# 脑健康数据平台完整克隆部署说明书

## 一、适用环境

- Ubuntu Server 24.04 LTS，amd64/x86_64；
- 建议不少于 16GB 内存、8 核 CPU；
- `/data` 建议至少保留 100GB 可用空间；
- 已安装 Docker Engine 和 Docker Compose 插件；
- 服务器能访问医院内网；院外授权访问需另装 Tailscale。

## 二、传输后先校验

将完整目录复制到服务器，例如：

```bash
cd ~/Downloads/brain-health-platform-1.0.0-full-clone-20260810
sha256sum -c SHA256SUMS
```

必须全部显示 `OK`。任何一项失败都不要安装，应重新传输对应分卷或文件。

## 三、安装

```bash
cd ~/Downloads/brain-health-platform-1.0.0-full-clone-20260810
chmod +x scripts/*.sh
sudo ./scripts/install.sh
```

脚本会自动完成：导入离线镜像、生成服务器专用密码、恢复 MySQL/MongoDB/MinIO/Redis 数据、启动全部服务并执行健康检查。首次安装根据磁盘速度约需 10–40 分钟。

安装完成后访问：

```text
http://服务器固定内网IP
```

如修改 `.env` 中 `APP_PORT`，访问地址需增加端口号。

## 四、三个演示账号

```text
管理员：admin / Admin@2026
医生：doctor_demo / Doctor@2026
患者（试用者）：trial_demo / Trial@2026
```

首次验收通过后应立即在系统内修改密码。`.env` 包含服务密码，权限必须保持为 `600`，不得通过微信群发送其内容。

## 五、验收

```bash
sudo ./scripts/health-check.sh
sudo docker compose --env-file .env -f docker-compose.yml ps
```

随后按 `docs/完整克隆验收表.md` 检查角色权限、受试者、访视、量表、影像、遗传、实验室、搜索、导出和中文显示。

## 六、Tailscale 院外授权访问

服务器安装并登录医院指定的 Tailscale 账号：

```bash
curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up --hostname=brain-health-server
sudo tailscale serve --bg --http=80 127.0.0.1:80
```

仅邀请并批准的设备可访问。不得启用 Funnel，不得在路由器开放公网端口。医院的 Tailscale 管理员应启用设备审批，并在 ACL 中仅允许授权人员访问服务器 Web 端口。

## 七、常用命令

```bash
# 查看状态
sudo docker compose --env-file .env -f docker-compose.yml ps

# 查看日志
sudo docker compose --env-file .env -f docker-compose.yml logs --tail=200

# 重启
sudo docker compose --env-file .env -f docker-compose.yml restart

# 停止（不删除数据）
sudo docker compose --env-file .env -f docker-compose.yml stop

# 启动
sudo docker compose --env-file .env -f docker-compose.yml up -d
```

禁止执行 `docker compose down -v`，该命令可能删除数据卷。禁止手工删除 `DATA_ROOT`。

## 八、故障处理

- 登录显示服务器内部错误：先执行健康检查，再查看 `auth-service` 和 `gateway` 日志。
- 多个页面同时 500：检查业务容器是否退出，并查看 Redis/MongoDB 连接日志。
- 页面 502：确认 gateway 已启动，然后重启 frontend。
- Redis unhealthy：不要 `source .env` 后手工拼接 Redis command；以本包 Compose 数组配置为准。
- 中文乱码：不要使用会转换编码的编辑器保存 SQL、JSON、YAML 或 Shell 文件；重新从校验通过的交付包恢复。

## 九、回滚原则

安装脚本发现已有 `.full-clone-restored` 标记会停止，避免覆盖。再次安装前必须先备份整个 `DATA_ROOT` 和 `.env`。如本次安装失败，可停止当前 Compose 项目并恢复安装前备份；不要在没有备份的情况下清理目录。
