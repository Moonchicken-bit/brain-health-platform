# 脑健康数据平台医院内网部署说明书

## 1. 适用范围

本说明书用于在医院内网的一台 Ubuntu 24.04 x86_64 服务器上离线部署脑健康数据平台。系统采用 Docker Compose 运行，医院服务器不需要访问互联网。

建议配置：16 核 CPU、32 GB 内存、系统盘 200 GB、数据盘 2 TB 以上。影像数据增长较快，数据盘容量应按实际病例量扩容。最低测试配置为 8 核、16 GB 内存，但不建议用于多人并发。

## 2. 部署包内容

- `docker-compose.prod.yml`：生产环境服务编排
- `.env.example`：部署参数模板
- `images/brain-health-images.tar`：全部离线 Docker 镜像
- `sql/`：数据库初始化和升级脚本
- `scripts/`：安装、启停、检查、备份、恢复脚本
- `docs/`：部署和运维文档
- `SHA256SUMS`：文件完整性校验值

## 3. 部署前准备

医院信息科需准备：

1. Ubuntu 24.04 x86_64 服务器，设置固定内网 IP。
2. 已离线安装 Docker Engine 及 Docker Compose v2 插件。
3. 将数据盘挂载好，默认使用 `/data/brain-health`。
4. 防火墙允许临床电脑访问服务器 TCP 80 端口。
5. 服务器时间、时区设置正确，建议时区为 `Asia/Shanghai`。

检查命令：

```bash
uname -m
docker version
docker compose version
timedatectl
df -h
free -h
```

`uname -m` 应显示 `x86_64`。

## 4. 复制并校验部署包

把压缩包复制到服务器，例如 `/opt/install/`，执行：

```bash
cd /opt/install
tar -xzf brain-health-platform-1.0.0-pilot-linux-amd64.tar.gz
cd brain-health-platform-1.0.0-pilot
sha256sum -c SHA256SUMS
```

所有项目显示 `OK` 才可继续。若校验失败，应重新复制部署包。

## 5. 配置

首次安装通常无需手工创建 `.env`，安装脚本会自动生成随机数据库密码、JWT 密钥等。

若 Web 端口 80 被占用，安装前执行：

```bash
cp .env.example .env
nano .env
```

修改：

```text
APP_PORT=8080
DATA_ROOT=/data/brain-health
```

`.env` 含服务密码，只允许管理员读取：

```bash
chmod 600 .env
```

## 6. 一键安装

```bash
chmod +x scripts/*.sh
sudo ./scripts/install.sh
```

首次导入离线镜像和初始化数据库可能需要 10–30 分钟。安装完成后访问：

```text
http://服务器固定内网IP
```

如果修改过 `APP_PORT`，地址为 `http://服务器IP:端口`。

## 7. 首次登录和安全交接

试运行初始账号：

| 角色 | 用户名 | 初始密码 |
|---|---|---|
| 系统管理员 | `admin` | `Admin@2026` |
| 医生 | `doctor_demo` | `Doctor@2026` |
| 受试者/患者 | `trial_demo` | `Trial@2026` |

这些账号仅供部署验收。首次登录后必须立即修改管理员密码，并由管理员创建医院自己的机构、项目、医生和患者账号；不再使用的演示账号应停用。

生产录入前还应确认：

- 服务器仅在医院内网访问，不做公网端口映射。
- `.env` 未通过聊天、邮件或普通共享盘传播。
- 数据目录和备份目录仅授予服务器管理员权限。
- 医院制定账号、密码、备份保留和审计制度。

## 8. 验收检查

查看服务：

```bash
sudo ./scripts/status.sh
sudo ./scripts/health-check.sh
```

浏览器验收：

1. 管理员、医生、受试者三个角色均可登录。
2. 管理员可管理机构、项目及用户。
3. 受试者可填写访视表单。
4. 医生可查看受试者提交后的评分结果。
5. 测试上传一个小型综合 ZIP/RAR，确认能识别影像、遗传、实验室和附件。
6. 退出并重新登录，确认数据仍存在。

## 9. 日常运维

```bash
# 启动
sudo ./scripts/start.sh

# 停止
sudo ./scripts/stop.sh

# 查看状态
sudo ./scripts/status.sh

# 查看全部实时日志
sudo ./scripts/logs.sh

# 只看网关日志
sudo ./scripts/logs.sh gateway
```

服务器重启后 Docker 会按策略自动恢复容器，也可手工运行 `start.sh`。

## 10. 备份与恢复

每天数据库备份：

```bash
sudo ./scripts/backup.sh database
```

定期完整冷备份（期间系统短暂停止，且需要足够磁盘空间）：

```bash
sudo ./scripts/backup.sh full
```

备份位于 `/data/brain-health/backups/日期时间/`。应再复制到医院独立备份设备，不能只保存在同一块数据盘。

恢复会覆盖当前数据，必须先停止临床使用并确认备份目录：

```bash
sudo ./scripts/restore.sh --confirm /data/brain-health/backups/20260731-120000
```

## 11. 离线升级

收到新版部署包后：

1. 先做完整备份。
2. 解压新版包。
3. 保留原 `.env`，复制到新版目录。
4. 执行：

```bash
sudo ./scripts/upgrade.sh
```

升级脚本会再次做数据库备份、导入镜像、执行数据库迁移并重建服务。

## 12. 常见故障

端口占用：

```bash
sudo ss -lntp | grep ':80 '
```

磁盘不足：

```bash
df -h
sudo du -sh /data/brain-health/*
```

容器异常：

```bash
sudo ./scripts/status.sh
sudo ./scripts/logs.sh
```

页面打不开时，依次确认服务器 IP、TCP 端口、防火墙、容器状态和健康检查。不要直接清空 `/data/brain-health`，该目录包含全部业务数据。

## 13. 医院信息科交接清单

- 服务器固定 IP、机房位置和负责人
- 部署包版本与 SHA256 校验结果
- `.env` 的安全保管位置
- 管理员账号已改密
- 演示账号已停用或改密
- 每日备份任务和异机备份责任人
- 恢复演练记录
- 内网访问范围与防火墙规则
- 故障联系人和版本升级记录
