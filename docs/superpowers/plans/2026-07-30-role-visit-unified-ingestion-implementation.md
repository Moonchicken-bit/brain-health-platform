# 角色、患者量表与访视统一导入实施计划

依据设计文档：
`docs/superpowers/specs/2026-07-30-role-visit-unified-ingestion-design.md`

## 阶段一：患者量表闭环

1. 新增患者角色和患者用户—受试者唯一绑定表。
2. 在认证信息中返回绑定的受试者 ID。
3. 新增管理员/医生为受试者开通患者账号的接口。
4. 将前端菜单改为按角色生成；患者只显示“我的量表”。
5. 新增量表任务表和任务接口。
6. 创建访视后根据模板或当前启用量表生成任务。
7. 患者只能读取、保存和提交自己的任务。
8. 复用现有评分服务完成自动评分。
9. 医生评分总览展示患者任务状态和最终分数。
10. 补齐权限矩阵、数据越权、自动评分和浏览器端到端测试。

## 阶段二：管理员基础配置

1. 校正机构、项目接口的管理员权限。
2. 完成机构与项目的新增、编辑、停用。
3. 新增项目成员和医生数据范围维护。
4. 新增访视模板及版本表。
5. 新增量表题目、评分规则的草稿、发布、停用和版本管理。
6. 已有访视与作答保存版本快照。

## 阶段三：遗传动态字段

1. 新增表单、版本、字段、选项和值表。
2. 新增管理员字段配置接口和页面。
3. 第一批挂载点为遗传样本及遗传上传确认页。
4. 医生端根据已发布版本动态渲染并保存。
5. 增加字段停用、历史版本和审计测试。

## 阶段四：访视综合导入

1. 新增统一导入批次、文件项和模块任务表。
2. 把上传、解压和识别任务持久化。
3. 一次解压后分别调用影像、遗传、实验室识别器。
4. 新增医生确认与分类纠正页面。
5. 使用文件哈希与模块幂等键防止重复入库。
6. 支持模块独立重试和 `PARTIAL_FAILED` 状态。
7. 访视工作台展示模块摘要并链接专业页面。

## 阶段五：字段扩展与全系统回归

1. 将动态字段能力挂载到影像、实验室和访视表单。
2. 完成全平台、项目和表单三级生效范围。
3. 验证管理员、医生、患者完整权限矩阵。
4. 验证大压缩包、危险压缩包、断点恢复和重复上传。
5. 完成前后端构建、服务测试和浏览器端到端测试。
