# 医院服务器完整克隆交付设计

日期：2026-08-10

## 1. 目标

把当前已验证可用的脑健康数据平台完整迁移到医院 Ubuntu 24.04 服务器。部署后账号、权限、受试者、访视、量表题目与答案、评分、影像、遗传、实验室、导出记录、字段字典、上传文件和页面效果均与当前机器一致。医院内网可直接访问，获授权的院外设备通过 Tailscale 私网访问；数据库及中间件不得对外暴露。

## 2. 交付策略

采用“已运行镜像 + 一致性数据快照 + 外部资源 + 自动恢复脚本”的离线完整克隆方式。医院服务器不重新编译前后端，不依赖 npm、Node.js、Maven 或互联网拉取基础镜像，从而保证运行内容与本机一致。

交付物包括：

- 当前实际运行的全部 Docker 镜像及镜像摘要；
- MySQL 全库逻辑备份；
- MongoDB 全库备份；
- MinIO 对象和桶配置完整备份；
- 必要的 Redis 持久化数据或明确的可重建策略；
- `clinical_field_dictionary.json`、量表元数据及所有运行时外部资源；
- Ubuntu 24.04 生产 Compose、环境变量模板和 Tailscale 接入说明；
- 安装、恢复、检查、备份、回滚脚本；
- UTF-8 检查报告、文件清单、版本清单、数据数量基线及 SHA-256 校验文件；
- 部署说明书、账号说明、日常运维与故障排查文档。

## 3. 一致性快照

正式快照前进入短暂维护窗口，停止新增写入。按 MySQL、MongoDB、MinIO、Redis 的顺序生成带时间戳快照，并记录：数据库表及记录数、MongoDB 集合及文档数、MinIO 桶/对象数/总容量、镜像 ID 和摘要。所有快照完成后恢复本机服务。

快照不得只复制 Windows Docker volume。数据库使用官方导出工具，文件存储使用对象级备份，以保证 Windows Docker Desktop 到 Ubuntu Docker Engine 的兼容性。

## 4. UTF-8 与资源完整性

打包前扫描 SQL、JSON、YAML、Markdown、Shell、Java、TypeScript/Vue 及配置文件。文本应为 UTF-8（Shell 脚本使用 UTF-8 无 BOM 和 LF）。发现不可解码文件、替换字符或已知乱码模式时停止发布。

资源清单必须明确包含字段字典、量表题目、患者填写结果、初始化/迁移 SQL、前端静态资源和上传对象。清单中的每个文件记录相对路径、字节数和 SHA-256，安装前后分别校验。

## 5. 医院部署结构

医院服务器只向内网监听 Web 入口；MySQL、MongoDB、Redis、Elasticsearch、MinIO、RabbitMQ、Nacos 和管理端口只在 Docker 网络或 localhost 上监听。院外访问使用 Tailscale 私网，不启用 Funnel，不开放路由器公网端口。

生产密码在医院服务器首次安装时生成，不复用本机开发密码。恢复数据后执行数据库用户和应用密钥轮换；打包文件使用加密归档，解密密码通过独立渠道传递。

## 6. 恢复与回滚

安装脚本执行前检查 Ubuntu、磁盘、内存、Docker/Compose 版本、端口及校验和。若目标目录或 Docker 项目已存在，先生成可恢复备份，不覆盖未知数据。

恢复顺序为基础设施、数据库/对象数据、业务服务、网关、前端。任一步失败即停止并输出明确错误；不得继续运行半恢复环境。回滚通过停止新项目、恢复先前 Compose 和数据备份完成。

## 7. 全新环境恢复演练

最终打包前必须在全新的本机项目名和空卷中完成一次恢复演练，禁止复用当前运行卷。演练通过后才生成交付包。

验收至少包括：

- 管理员、医生、患者三个角色登录成功且菜单/权限正确；
- 受试者、访视、量表题目、答案、评分及测试记录数量与基线一致；
- 影像、遗传、实验室、搜索和导出接口返回 200；
- 影像详情、预览、下载和统一压缩包导入可用；
- 字段字典完整加载 10,290 项；
- MinIO 对象数量、总容量和抽样哈希一致；
- 中文页面、检验项目、量表和部署日志不存在新增乱码；
- 本机/医院内网入口可用，Tailscale 授权设备可用；
- 未授权设备以及数据库、中间件端口无法访问；
- 容器重启和服务器重启后自动恢复。

## 8. 最终交付目录

```text
brain-health-platform-full-clone/
├─ images/
├─ backups/mysql/
├─ backups/mongodb/
├─ backups/minio/
├─ backups/redis/
├─ resources/
├─ deploy/
├─ scripts/
├─ docs/
├─ manifest/
└─ SHA256SUMS
```

交付包按适合网盘传输的大小分卷；每个分卷单独记录 SHA-256。医院端合并/解压后必须先通过完整性校验，才允许执行安装。

## 9. 完成标准

只有当空环境恢复演练、数据数量比对、核心业务回归、UTF-8 检查、安全端口检查、重启恢复测试和文档复核全部通过，交付包才标记为可发布。任何缺失资源、数量不一致、接口 500、乱码或未授权端口开放都视为发布阻断项。
