# GitHub 私有源码仓库发布设计

日期：2026-08-19

## 目标

将脑健康平台的可复现源码、安全配置模板、数据库迁移脚本和使用文档发布到 GitHub 私有仓库，同时保证患者数据、服务密码、运行数据和大型构建产物不会进入 Git 历史。

## 发布方式

采用“私有源码仓库 + 独立部署包”方式：

- GitHub 私有仓库保存源代码、构建配置、Docker/Compose 配置、SQL 迁移、非敏感示例配置和文档。
- 已验证的约 7 GB 完整部署包继续通过阿里云盘、移动硬盘或点对点方式交付，不提交到普通 GitHub 仓库，也不使用 Git LFS 存放医学数据。
- 仓库默认分支为 `main`，首次提交在本地完成审计后再推送。

## 纳入仓库的内容

- 前端和全部后端服务的源代码。
- Maven、npm、Docker 和 Compose 构建配置。
- `sql/` 中的数据库结构与迁移脚本。
- 不含真实秘密的 `.env.example`、`.env.template`。
- 项目说明、开发文档及部署说明。
- 前端运行所需的非敏感静态量表/字段字典。

## 必须排除的内容

- `.env`、密钥、令牌、密码、证书私钥和本机凭据。
- `subject-service/data/unified-imports/` 等患者上传、解析与医学附件数据。
- `data/`、`uploads/`、`backups/`、数据库目录和对象存储快照。
- `target/`、`node_modules/`、`dist/`、JAR、Docker 离线镜像及日志。
- ZIP、RAR、7z、tar 等交付压缩包和超过 GitHub 100 MB 限制的文件。
- 临时文件、IDE 配置和操作系统生成文件。

## 实施步骤

1. 创建覆盖所有模块的根目录 `.gitignore`。
2. 在初始化 Git 前扫描文件名、内容和文件体积，检查密码、令牌、患者资料与大文件。
3. 生成面向开发者的根目录 `README.md`，说明架构、启动方式、配置方式和数据安全边界。
4. 初始化 Git，建立 `main` 分支，仅暂存审计通过的内容。
5. 对暂存区再次执行敏感信息、大文件和忽略规则验证。
6. 创建本地首次提交。
7. 在推送前展示 GitHub 账号、目标仓库名称及可见性，由用户确认后创建或关联私有仓库并推送。

## 安全检查与失败处理

- 任何大于 100 MB 的暂存文件均阻止提交。
- 检出疑似密码、访问令牌、私钥或患者数据时，先从提交范围移除并复核；不通过简单删除提交来处理已经进入历史的秘密。
- `.env.example` 和 `.env.template` 只允许占位值，不允许真实服务密码。
- 若首次推送失败，保留本地提交，不修改或删除用户源文件；修复远端认证或仓库地址后重试。

## 验收标准

- Git 暂存区不包含患者上传、数据库快照、运行日志、构建产物或压缩部署包。
- 暂存区无超过 100 MB 的文件。
- 敏感信息扫描无真实凭据命中。
- 私有仓库可克隆，源代码和文档完整。
- 克隆后能够依据 README 重新构建系统；完整业务数据仍通过独立部署包恢复。
